# WeTalk_v3 业务逻辑优化建议 v1（对标成熟产品）

> 日期：2026-09-07
> 性质：方案建议稿，未改动任何代码。
> 参考对象：Woebot / Wysa（循证心理工具）、Replika / Character.AI（AI 陪伴）、
> 学术 LangGraph 心理对话框架、加州 AI 陪伴法规与 FTC 关注点。

## 0. 结论

WeTalk_v3 的业务骨架（意图路由 → 危机分层 → 深度倾诉 → 质量反思 → 记忆收尾）
与市场主流模块基本同构，方向正确。主要差距集中在六处：

1. 危机协议不够完整（二分类拦截、无否认处理、危机后直接结束、无风险记忆与回访）；
2. 治疗内容没有结构化（无情绪打卡、无技能模块、无"作业"与回访）；
3. 记忆没有闭环（只倾诉后写入、无会话摘要、无用户可见/可改/遗忘机制）；
4. 检索太单一（纯 BM25 字面匹配）；
5. 没有人机协同与合规披露（无人工出口、无 AI 身份/边界披露、演示级鉴权）；
6. 成本结构不健康（一次倾诉最多约 5~6 次大模型串行调用）。

---

## 1. 危机路径：从"二分类拦截"升级为"分层安全协议"（P0）

现状：关键词快检 + 一次 LLM 二分类（high/normal）→ 高危就给固定话术和热线并直接 END。

建议：

- **风险不是二元开关**：参考临床筛查（如 C-SSRS）的维度（想法/计划/手段/时间），
  把危机复核改为三档：高危 / 需关注 / 正常。"需关注"走追问澄清，而不是直接放行或直接贴热线。
- **用户否认风险时不能简单降级**：高危确认后若用户说"你误会了"，应温和追问并保持观察，
  而不是把危机状态直接降回 normal。
- **危机回应后不要直接 END**：改为多轮"危机时刻陪伴协议"：
  表达关心 → 提供热线 → 确认当下安全（身边是否有人/能否联系到人）→ 允许用户继续说话。
- **危机要有记忆与回访**：risk 条目（高敏、用户可删）写入长期记忆；
  下次会话开头温和回访："上次你说很难，现在怎么样？"
- **失败要 fail-safe**：危机场景的输出检查若解析失败，默认应"转人工/再次确认"，
  不能像普通对话一样默认放行。
- **合规披露**：向用户明确"我是 AI，不是真人、不是医生"；
  高风险场景给出明确的危机服务渠道（热线/短信）。

参考：

- Wysa 分层安全架构与 RAG 研究：https://aipulselab.tech/news/retrieval-augmented-generation-in-llms-for-mental-health-quantifying-the-incremental-contribution-of-retrieval-within-a-layered-safety-architecture-ec978f
- Common Sense Media 对 Wysa 危机路径"单次否认即离开"的批评：https://institute.commonsensemedia.org/sites/default/files/risk-assessments/csm-ai-risk-assessment-ai-mental-health-apps-05052026_1.pdf

## 2. 治疗内容：从"共情+RAG"变成"结构化干预"（P0/P1）

现状：deep_talk 本质是"温暖共情 + 检索知识片段 + 泛泛质量反思"，没有可复用的干预框架。

建议：

- **开场情绪打卡**：每次进入倾诉先做轻量情绪/睡眠/能量自评，
  数据写入 emotion_state 记忆，也让开场有抓手；
- **技能模块化**：把知识库内容组织成可执行技能
  （思维记录表、行为激活、呼吸练习等），倾诉后可引导做一个小练习；
- **结尾约"作业"**：给用户一个具体的小尝试，下次会话回访完成情况，
  这是制造"连续性"的核心机制，也是自画像/故事图要呈现的"进展"；
- **模式路由**：把 deep_talk 拆成"倾听陪伴"与"技能引导"两条子路径，
  按用户状态路由，而不是每轮都用同一套提示词。

参考：Woebot 的结构化 CBT 会话与技能练习、Wysa 的情绪打卡：
https://www.iatrox.com/blog/ai-mental-health-wysa-limbic-woebot-nice-guidance-uk

## 3. 记忆：从"倾诉后存几条"变成"用户可感知的记忆闭环"（P1）

现状：只在深度倾诉结束后写入；按类别覆盖旧值；无会话摘要；
无用户可见/可改/遗忘机制；读取只发生在 deep_talk。

建议：

- **所有入口都能存**：闲聊中的自我介绍、求助中的家庭信息等都应能进入长期记忆
  （配合已定稿的高敏确认弹窗流程）；
- **会话摘要（session_note）**：对标 Character.AI 的 Story Memories，
  是长程记忆与故事图的关键数据源，建议重新评估此前"搁置"的决定；
- **记忆管理 UI**：用户能查看"你记住了我什么"、能删除、能关闭自动记录，
  这是自画像页的自然延伸，也是信任与合规的基础；
- **存情绪轨迹而不只是事件**：事件是点，情绪状态是线，
  自画像/故事图要展示的是这条线的走向（不只是事实清单）。

参考：

- Character.AI 记忆机制（Facts 可编辑/禁用、Memory Usage、Story Memories）：
  https://blog.character.ai/memory/
- Replika 记忆重置事故与"记忆需要稳定、可被用户管理"的教训：
  https://kar.kent.ac.uk/109186/1/123ANNA_20XYGKOU_PhD_20Thesis.pdf
- "记忆只存事实、不存情绪状态变化"的批评：
  https://qu3ry.net/articles/affective-state-replika.pdf

## 4. 检索：从"BM25 字面匹配"升级为"混合检索 + 来源可溯"（P2）

现状：求助/倾诉均使用 BM25 关键词匹配；知识片段无来源信息；
本地已有未启用的 embedding 模型（paraphrase-multilingual-MiniLM-L12-v2）。

建议：

- BM25 + 向量检索融合（本地 embedding 模型已就位，成本低）；
- 知识片段带上来源（文件名/章节），必要时前端展示"参考来源"；
- 检索不到时明确说"资料有限 + 建议专业渠道"，不臆造；
- 注意 Wysa 研究的结论：RAG 会提高高风险识别率但同时增加误报，
  检索结果不能当唯一权威，须配合分层安全路由。

参考：https://aipulselab.tech/news/retrieval-augmented-generation-in-llms-for-mental-health-quantifying-the-incremental-contribution-of-retrieval-within-a-layered-safety-architecture-ec978f

## 5. 人机协同与合规披露（P0/P1）

现状：纯自动、零人工出口；演示级鉴权（admin/123456，前端模拟）；
无知情同意、无 AI 身份/边界披露；无风险事件日志。

建议：

- **风险事件看板**：记录用户触发过几次危机、转介话术是否送达，供运营回访
  （对标 Wysa 的混合架构：被标记的高风险对话进入人工复核）；
- **正式鉴权与知情同意**：长期记忆保存敏感个人信息，
  上线前必须有正式登录鉴权、隐私说明与存储授权；
- **边界披露**：onboarding 与关键对话中声明
  "AI 不是真人、不是医生、不能替代治疗/危机服务"；
- **防情感依赖设计**：周期性休息提醒、关系边界话术
  （FTC 正在关注 AI 陪伴对未成年人情感依赖的影响）。

参考：https://www.iatrox.com/blog/ai-mental-health-wysa-limbic-woebot-nice-guidance-uk

## 6. 成本与链路：按任务分配模型能力（P2）

现状：一次倾诉链路为
classify → crisis_check → deep_talk（可能两轮：工具调用前后）→ reflect → remember，
约 5~6 次大模型串行调用。

建议：

- classify / reflect 等"判断"任务使用便宜快速的模型或规则（关键词快检已具备）；
- reflect 不每轮都跑：仅在危机/医疗话题或回答超长时启用，普通倾诉跳过或异步执行；
- remember 与会话摘要移到回复流结束后的后台任务，用户无需等待记忆写完；
- 参考 LangGraph 心理框架（如 MindBridge）的思想：
  把"安全治理"和"最终检查"做成可独立开关的层，而不是绑死在倾诉链上。

参考：MindBridge 模块化多智能体心理对话框架：
https://www.essays.se/essay/c5396cf853/

## 7. 落地顺序

| 优先级 | 模块 | 主要内容 |
|---|---|---|
| P0 安全线 | 危机协议 | 风险三档 + 追问澄清 + 否认处理；危机后保持在场；risk 记录与回访；危机路径 fail-safe；AI 身份披露 |
| P1 记忆闭环 | 长期记忆落地 | 六类模型 + 全节点注入 + 会话摘要 + 记忆管理页（自画像/故事图顺势做） |
| P1 治疗结构 | 情绪打卡 + 技能模块 | 开场状态采集；结构化技能引导；结尾"作业"与回访 |
| P2 工程 | 混合检索、模型分层、异步收尾、评测集 | 启用本地 embedding；小模型跑判断；后台写记忆；危机语料红队测试与指标看板 |
